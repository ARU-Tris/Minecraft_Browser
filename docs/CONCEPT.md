학교·Gmail·구름은 위치가 지정되지 않아 둘째 줄 왼쪽에 배치했다. 이외 인벤토리 칸과 장비 칸은 비운다. 이후 사용자가 직접 옮기거나 추가한 값은 유지한다.

기존 사이트를 정리하는 요청은 한 번의 마이그레이션으로 반영한다. 이전 저장 원문을 `craftside:inventory:v1:before-curated-20261019`에 먼저 보존하고 `layout: curated-20261019`를 기록한다. 백업 또는 새 배치 저장이 실패하면 이전 값을 보존한다. 이미 이 표식이 있으면 초기 배치를 재적용하지 않는다.

추가·편집 화면의 **아이콘 지정**은 별도 크리에이티브 인벤토리를 연다. 제공한 팩의 검색 인벤토리 패널과 게임의 분류 탭·스크롤바 텍스처를 사용한다. 9×5 선택 칸, 현재 핫바 미리보기, 7개 분류, 한국어/영문/ID 검색을 제공한다. 휠·스크롤바·방향키로 목록을 옮기고 아이템을 누르면 작성 중인 화면으로 돌아온다. 선택창 취소는 이름·주소·기존 아이콘을 보존한다. 최종 추가/저장 시에만 반영한다.

현재 카탈로그는 852종이다. 나침반은 실제 `compass_16.png`, 일반 아이템은 원본 PNG, 제작대 등 단일 큐브 블록은 실제 모델의 면 텍스처를 직교 투영한 뷰다. 한국어는 설치된 동일 버전의 공개 언어 자산을 사용한다. 틴트/다중 요소가 필요한 미지원 모델은 임의 그림으로 대체하지 않고 제외한다. 고정 도구 5개와 다른 사이트가 사용하는 아이템은 회색으로 표시하고 중복 배정을 막는다.

기존 사이트의 아이콘도 바꿀 수 있다. 착용 중인 아이콘이 다른 부위/일반 아이템으로 바뀌면 빈 인벤토리 칸으로 돌아온다. 빈칸이 없거나 다른 창이 먼저 해당 아이콘을 배정했다면 저장을 거절하고 기존 상태를 보존한다.

## 6차 · 시간대·효과음·음악·뉴스

인벤토리 아래의 Add site 버튼을 제거합니다. 고정 제작대, 빈 슬롯 클릭과 설정에서 추가합니다. 물 양동이 뉴스 바로가기는 핫바 9번에 넣고, 기존 북마크 원문을 별도 키로 백업한 뒤 해당 칸의 아이템을 빈칸으로 옮깁니다. 이후에는 사용자의 재배치·이름·삭제를 보존합니다.

배경은 4초, 시간대 음악은 6초의 교차 페이드입니다. 낮에는 하루별 순서를 섞고 같은 2시간 구간에는 선택을 유지합니다. `Date`의 로컬 시간을 직접 읽으며, 30초마다 및 절전/화면 복귀 때 갱신합니다. 시안 비교 도구의 World는 시간대를 검토하는 임시 제어이고 기본은 Computer time입니다.

첫 사용자 조작 후 음악을 시작하고, 사이드바에서 재생/정지·이전/다음 곡·볼륨을 직접 제어합니다. 설정에서는 효과음 전체 켜기/끄기·볼륨·테스트를 제공합니다. 일반 인벤토리 아이템 이동에 별도의 바닐라 사운드가 없으므로 실제 UI 클릭음을 작게 사용하고, 갑옷에는 실제 착용음을 연결합니다. 효과음 끄기는 알림·동굴음을 포함합니다. 음악 끄기는 음악과 동굴 환경음을 함께 멈춥니다.

공식 뉴스는 `tools/serve.py`의 고정된 읽기 API로 15분마다 확인합니다. 첫 확인은 알림 없이 기준을 만들고, 이후 새로운 기사만 실제 advancement 배경·오른쪽 슬라이드·toast in/out·challenge_complete 효과음으로 표시합니다. 한 번 본 기사는 다시 띄우지 않습니다. 미리보기에는 Preview를 붙이고 실제 신규 기사 기록에는 영향을 주지 않습니다. 시안이 닫혀 있는 동안의 서비스/OS 알림은 범위에 없습니다.

음악·환경 이미지·알림 GUI는 `assets/ambience/`의 별도 사본이며 `sources.json`에 원본 asset index/entry 및 해시를 남깁니다. 기존 ref·게임 원본·아이콘/스킨 자료를 수정하지 않습니다.

## 안 읽은 알림 · 인챈트

알림이 전달됐다는 기록과 사용자가 확인했다는 기록을 분리합니다. 새 뉴스 중 아직 확인하지 않은 기사는 `craftside:unread:v1`에 저장하며 뉴스 바로가기에 실제 리소스 팩의 인챈트 광택을 붙입니다. 토스트 닫기·시간 만료는 확인 처리가 아닙니다. 실제 기사 링크는 한 건, 뉴스 목록 바로가기는 남은 전체를 확인 처리합니다. 최초 기준과 꺼진 알림, 미리보기는 안 읽은 항목을 만들지 않습니다. 토스트는 최대 3개여도 같은 확인에서 발견한 새 기사는 모두 안 읽음 상태로 남습니다.

광택은 슬롯 번호나 아이템 ID 대신 북마크 URL의 서비스에 연결합니다. 물 양동이·Gmail을 옮기거나 이름/아이콘을 바꿔도 상태가 따라갑니다. 실제 선택 아이템의 알파에 glint 텍스처를 마스킹하므로 갑옷 등으로 바꿔도 같은 원칙을 사용합니다. Settings의 20초 인챈트 미리보기는 실제 상태를 저장·변경하지 않습니다.

Gmail은 사용자가 이 브라우저의 Gmail에 일반 로그인한 세션을 재사용합니다. 별도의 Google OAuth 프로젝트·클라이언트 JSON·Gmail API 키 설정을 사용자에게 요구하지 않습니다. Gmail의 받은편지함 안 읽음 배지/제목을 읽고 메일 본문·제목·쿠키·토큰을 수집하거나 읽음 처리하지 않습니다. Gmail 열기만으로 광택을 끄지 않으며 실제 안 읽은 수 0을 확인하면 끕니다. 계정 전환과 로그아웃에서는 이전 계정 수치를 버립니다.

현재 웹 시안은 다른 브라우저의 Gmail 탭을 읽을 수 없습니다. `browser/gmail-reader.cjs`·`gmail-session.cjs`와 UI 브리지 계약은 소스/모의 검사 단계이며 네이티브 엔진에는 아직 연결하지 않았습니다. 실제 로그인 호환성, Google의 DOM 변경 대응, 브라우저 세션 복원과 백그라운드 Gmail 뷰는 해당 엔진 단계에서 검증합니다. Gmail을 로그인했다고 현재 시안이 실시간 수신을 추적한다고 표시하지 않습니다.

## 리소스팩 · 실제 ZIP 가져오기

설정에 Resource packs를 추가합니다. Java Edition ZIP 선택/드롭 → Available → Use pack → Selected → Apply packs로 적용합니다. 선택 목록의 위쪽이 우선이며 각 파일은 하위 팩과 기본 리소스에 차례로 폴백합니다. Default는 제거하지 못합니다. Cancel은 임시 선택/추가/제거를 버리고, Use defaults를 적용하면 기본 리소스로 돌아갑니다.

ZIP은 브라우저에서 직접 해석하고 별도 IndexedDB에 Blob과 선택 순서를 원자적으로 저장합니다. 서버 업로드·외부 URL 로딩·게임 폴더 변경은 없습니다. 북마크·플레이어 스킨·언어·음악 선호 저장과 분리합니다. 저장이 실패하거나 다른 창의 revision이 바뀌면 현재 화면과 이전 저장값을 유지합니다.

26.2 / 리소스 형식 88.0의 pack.mcmeta 신·구 필드와 overlays를 사용합니다. 아이템 PNG/레이어·정적 cuboid 부모 모델·namespace, GUI/크리에이티브/버튼/장비 슬롯·갑옷·glint·도전과제, 아이템 프레임 애니메이션, 낮 파노라마와 일치하는 음악/사운드를 교체합니다. 손상도/조건부 모델은 브라우저 아이템의 기본·정지·GUI 상태를 선택합니다. 구형 widgets.png/armor layer 경로도 변환하며 고해상도 GUI의 버튼 테두리를 보정합니다. 동굴·노을·밤 배경 일정과 사용자 스킨은 팩으로 덮어쓰지 않습니다.

Java 팩의 모든 게임 기능을 재현하는 것은 아닙니다. 셰이더·모드 기능·팩 폰트·특수/복합 엔티티 렌더러는 지원하지 않습니다. 복잡한 아이템 모델은 기본 아이콘으로 돌아가고 건수를 표시합니다. 파일/PNG/CRC/압축 해제 한도를 검사하며 문제가 있는 팩은 기존 적용값을 대체하지 않습니다. 표준 ZIP 해석은 내장 DecompressionStream을 사용하므로 팩 적용에 외부 CDN 라이브러리·Python 설치가 필요하지 않습니다.

공개 기본 모델/경로 표는 `assets/resource-base.json`과 출처 JSON에 보존합니다. 자동 검사와 실제 제공 팩·Golden Days·합성 진단 팩의 렌더/복원 확인은 `design/evidence/v9/`로 분리합니다. 이 기능은 실제 동작하는 웹 시안의 리소스 교체 기능이며, 외부 사이트를 탑재한 네이티브 브라우저 구현 완료를 뜻하지 않습니다.

기술 근거: [Mojang · pack.mcmeta 형식](https://www.minecraft.net/en-us/article/minecraft-snapshot-25w31a), [Mojang · resource overlays](https://feedback.minecraft.net/hc/en-us/articles/18619031671821-Minecraft-Java-Edition-Snapshot-23w31a), [MDN · DecompressionStream](https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream/DecompressionStream).

## 제안하는 시각 방향

새 탭은 Minecraft 인벤토리의 화면 구조를 직접 따른다. 장비 칸 옆 검은 플레이어 미리보기, 작업대의 2×2 도구와 결과 슬롯, 아래의 3×9 보관함과 9칸 핫바를 구성한다. 회색 패널의 밝고 어두운 모서리, 안으로 파인 슬롯과 픽셀 아이템을 사용한다. 사이드바도 같은 회색 UI로 맞추고 선택만 잔디색으로 표현한다.

웹사이트 본문의 서체·색·배치는 사이트 것을 유지한다. 브라우저가 네이버, 문서 편집기, 동영상 페이지까지 픽셀 글꼴로 강제 변경하지 않는다. 내가 만든 새 탭과 설정에는 테마를 충분히 드러낸다.

원본 폰트 검사에서 Minecraft는 107개 코드포인트, 갈무리11은 20,924개 코드포인트를 확인했다. Minecraft에는 검사에 사용한 한글 문자가 없고, 갈무리11에는 있다. 그래서 영문 이름과 한글 UI의 역할을 나눈다. 제공된 TTF를 그대로 복사했으며 폰트를 변형하지 않았다.

### 기본 언어와 전환

새 프로필은 OS/브라우저 언어를 자동 감지하지 않고 **English**로 시작한다. **Settings → Language**에서 English 또는 한국어를 고르면 즉시 전환하고 `craftside:language:v1`에 저장한다. 새로고침 후 선택을 복원하며, 저장 실패 시 이전 언어와 선택을 유지하고 오류를 표시한다. 다른 창에서 언어를 바꾼 경우에도 UI에 반영한다.

대상은 자체 사이드바·탭/페이지 제목·주소/설정/스킨/북마크 대화상자·크리에이티브 인벤토리·아이템 이름·툴팁·빈 상태·안내와 오류·자체 설계 예시다. 언어 선택지는 각 언어의 이름인 English / 한국어로 표시한다. 실제 외부 사이트의 내용은 번역하지 않는다.

`locales.js`에서 영어/한국어 쌍을 관리하고, `i18n.js`가 기존 템플릿과 동적 UI를 적용한다. 동적 조합은 현재 언어로 다시 그리며 상태는 `data-panel` 등 언어와 독립된 값으로 판단한다. 사용자 사이트 이름·주소·스킨 파일명·작성 중인 입력은 자동 번역에서 제외한다. 기본 학교/지도/구름 이름만 언어에 맞춰 표시하고 원본 저장값은 유지한다.

## 화면 골격

```text
열어 두기
┌────────────────┬──────────────────────────────────────┐
│ 로고 / 접기    │                                      │
│ 이동 / 주소    │                                      │
│ 세로 탭        │            웹사이트                  │
│ 새 탭          │          상단 탭 바 없음              │
│ 즐겨찾기       │                                      │
│ 광고 방패      │                                      │
│ 설정           │                                      │
└────────────────┴──────────────────────────────────────┘

접고 집중하기
┌───────────────────────────────────────────────────────┐
│                                                       │
▏                 웹사이트 전체 영역                    │
│                                                       │
└───────────────────────────────────────────────────────┘
```

사이드바에 탭, 주소, 뒤로·앞으로·새로고침, 즐겨찾기, 다운로드, 광고 방패, 설정을 모은다. 별도의 영구 상단 탭 바·주소 바는 두지 않는다.

### 세 가지 상태

| 상태 | 페이지 너비 | 동작 |
| --- | --- | --- |
| 고정 | 사이드바 폭만큼 줄어듦 | 페이지 옆에 두고 오래 작업. 토글로 접기 |
| 잠깐 열기 | 유지 | 페이지 위에 겹쳐 열기. 페이지 클릭 또는 Esc로 닫기 |
| 닫힘 | 사용 가능한 클라이언트 영역 전체 | 고정 레일 없이 작은 왼쪽 손잡이만 남음 |

데스크톱 시안은 기본 264px, 작은 화면은 246/238px로 비교한다. 실제 앱에서는 폭 조절과 마지막 상태 복원을 제공할 수 있다. 이 숫자는 시안의 제안값이며 구현 완료나 사용성 측정 결과가 아니다.

사이드바가 닫혀도 웹사이트는 살아 있고 입력 중인 내용과 탭은 유지되어야 한다. 패널을 닫는 동작으로 탭을 재로딩하지 않는다. 왼쪽 손잡이는 전체 높이를 가로채지 않는 작은 영역이다. 실수로 열리는 것을 줄이기 위해 기본은 **클릭**으로 열고, 마우스 올리기로 여는 옵션은 이후 검토한다.

고정 패널과 겹침 패널을 별도 상태로 둔 이유는 페이지 재배치를 줄이면서 주소나 탭만 잠깐 바꾸기 위해서다. 600px 이하의 시안은 안전하게 겹침으로 동작한다. 이 프로젝트의 주 대상은 Windows 데스크톱이다.

### 닫혀 있을 때의 주소·창 제어

- `Ctrl+L`: 중앙에 작은 픽셀 주소 입력창. 주소를 입력한 뒤 닫히고 원래 작업 화면으로 복귀.
- `Ctrl+B`: 사이드바 열기·접기. 실제 문서 편집기의 굵게 단축키와 충돌하지 않도록 입력 필드에서는 가로채지 않기. 구현 단계에서 사용자 지정도 고려.
- `Esc`: 주소 입력창·설정·임시 사이드바 순으로 닫기. 웹 작업의 Esc와 충돌 여부는 구현 단계에서 검증.
- `Ctrl+T/W/Tab`, `Alt+←/→`, `Ctrl+R` 등 일반 브라우저 키는 실제 앱에서 유지하는 방향.
- 최소화·최대화·닫기·창 이동은 **미구현 설계 항목**. 개발 단계에서 사이드바 헤더에 명시적인 창 버튼과 드래그 영역을 두고, 접었을 때는 왼쪽 손잡이로 다시 접근할 수 있게 한다. 상단 바를 영구히 차지하지 않는 별도 창 메뉴를 검토한다. 네이티브 창 이동·리사이즈·최대화·Alt+F4와 접근성을 실제 Windows에서 검증해야 한다.
- OS 작업 표시줄까지 숨기는 전체 화면과 사이드바를 접는 집중 화면은 별도 기능. 이번 시안의 닫힘은 집중 화면이다.

시안 안에는 작동하지 않는 창 닫기·최소화 버튼을 장식으로 넣지 않았다. 실제 앱에서 창 버튼은 반드시 접근 가능하게 구현한다.

## 듀얼 뷰 · 두 페이지와 하나의 사이드바

```text
┌──────────────┬──────────────────┬──────────────────┐
│ 공통 사이드바│   왼쪽 페이지    ┃   오른쪽 페이지  │
│ 주소 / 이동  │                  ┃                  │
│ 전체 탭 목록 │                  ┃                  │
│ 광고 / 설정  │                  ┃                  │
└──────────────┴──────────────────┴──────────────────┘
                                 ↔ 비율 조절
```

- 사이드바의 탭을 페이지 영역 오른쪽 또는 왼쪽에 끌어 놓으면 해당 위치에 배치한다. 끄는 동안 두 드롭 영역과 배치 안내를 표시한다.
- 탭 옆의 작은 분할 버튼과 사이드바의 듀얼 뷰 버튼으로도 같은 동작에 접근한다. 검토 도구의 듀얼 뷰 버튼은 작업 노트·읽는 시간을 예시 쌍으로 연다.
- Dual view 토글로 분할을 닫으면 오른쪽을 선택 중이었더라도 왼쪽 페이지를 유지한다. 검토 도구·사이드바·인벤토리의 토글에 같은 규칙을 적용한다. 각 페이지의 ‘이 화면만 보기’를 명시적으로 누른 경우에는 해당 페이지를 유지한다.
- 페이지를 클릭하거나 키보드로 포커스를 옮기면 해당 쪽이 활성화된다. 공통 주소창·뒤로·앞으로·새로고침은 활성 페이지에만 적용한다. 녹색 제목과 탭 목록의 L/R 표시로 현재 배치를 구분한다.
- 두 페이지는 별도 탭 인스턴스를 사용한다. 같은 예시 사이트를 양쪽에 열어도 체크박스 등 입력 상태가 서로 섞이지 않는다. 사이드바를 접거나 분할을 해제해도 열어 둔 탭은 보존한다.
- 가운데 경계는 드래그와 방향키로 조절한다. 현재 제안 범위는 28:72~72:28, 더블클릭하면 50:50이다.
- 각 화면 제목 옆 ×는 **그 화면만 보기**이며 탭 삭제가 아니다. 탭 삭제는 공통 탭 목록의 닫기 버튼이다.
- 사이드바를 접으면 두 페이지가 함께 넓어지고, 잠깐 열기는 두 페이지 너비를 바꾸지 않는다.

현재 작동 범위는 한 브라우저 시안 안에서의 탭·페이지 드래그 배치다. 별도의 Windows 최상위 창을 이 창으로 끌어와 합치는 기능은 실제 데스크톱 앱 구현 단계에서 다룰 별도 항목이다. 두 실제 외부 사이트의 렌더링·입력·메모리·보안 격리 검증도 이후 단계다.

## 새 탭

새 탭은 내 플레이어가 서 있는 인벤토리다. 제공한 VanillaTweaks의 클래식 파노라마를 배경으로 쓰고, `inventory.png`의 176×166 영역을 원래 비율로 표시한다. 장비·플레이어·제작·보관함·핫바를 해당 텍스처의 실제 좌표에 맞춘다. 검색창과 사이트 추가는 인벤토리 바깥에 두어 슬롯 구조를 바꾸지 않는다.

왼쪽에는 장비 슬롯 네 칸과 사용자 플레이어, 오른쪽에는 제작 도구를 둔다. 결과 슬롯의 다이아몬드는 사이트 추가를 연다. 보관함 27칸과 번호가 있는 핫바 9칸은 모두 북마크를 저장하고 이동할 수 있는 실제 칸이다. 아이템과 장비 빈칸 아이콘은 게임 PNG를 nearest-neighbor 방식으로 표시한다. 이전에 직접 그린 북마크 아이콘은 사용하지 않는다.

### 사용 자산

| 자산 | 실제 출처 |
| --- | --- |
| 인벤토리·번호 핫바·파노라마·일부 너깃 아이템 | 사용자 `VanillaTweaks_r106307_MC26.3.x.zip` |
| 팩에 없는 기본 아이템·장비 슬롯·버튼·착용 갑옷 | 설치된 `.minecraft/versions/26.2/26.2.jar` |
| 기본 플레이어 | 사용자 `ref/ARU_Tris.png`의 원본과 동일한 사본 |
| 폰트 | 기존 사용자 Minecraft·갈무리11 ZIP |

아이콘 카탈로그는 평면 아이템·나침반 프레임·큐브 블록 뷰를 포함해 852종이며 이 중 착용 가능한 갑옷은 25종이다. 팩의 같은 경로가 있으면 기본 게임보다 우선한다. 애니메이션·동적 색상·복합 모델이 필요한 유형은 지원 범위에 따라 제외했다. 게임 버전 자체를 26.3으로 변경한 것이 아니며, 복사한 기본 자산의 버전은 실제 발견한 26.2이다. 각 파일의 원본·ZIP 내부 경로·SHA-256과 블록 뷰의 입력 텍스처는 `assets/minecraft/sources.json`에 기록한다. 게임의 모드·저장·설정·계정 파일은 수정하지 않는다.

### 인벤토리 북마크

- 아이템 클릭은 사이트를 연다. 작업 노트·읽는 시간은 내부 예시 화면이고, http/https 북마크는 호스트 브라우저 새 탭에서 연다. 현재 HTML 시안 안에서 외부 사이트를 직접 렌더링하는 기능은 아니다.
- 아이템을 빈칸으로 끌면 이동하고, 다른 북마크 위로 끌면 위치를 바꾼다. 보관함과 핫바를 자유롭게 오갈 수 있다.
- 빈칸 클릭 또는 사이트 추가에서 이름·주소를 입력한다. 최초 아이콘은 이미 배정된 유형·고정 도구를 제외하고 무작위로 제안한다. ‘아이콘 지정’에서 크리에이티브 인벤토리로 직접 고르고, 기존 사이트도 같은 방식으로 편집한다.
- 우클릭 메뉴에서 사이트를 편집·삭제하거나 갑옷을 착용·해제한다. 이름·주소 편집은 아이템과 위치를 유지한다. 삭제 직후에는 되돌리기를 제공한다.
- 키보드는 Space로 아이템을 들고, 방향키 또는 Tab으로 대상 칸에 이동한 뒤 Enter로 놓는다. Esc로 취소한다.
- `craftside:inventory:v1`에 북마크·36칸 위치·4개 장비 칸을 한 번에 저장한다. 저장 실패 시 변경을 되돌린다. 잘못된 기존 저장값을 읽으면 원래 값을 덮어쓰지 않고 보기 모드로 연다.
- URL은 http/https 및 정해진 내부 예시 주소만 허용한다. 코드 실행 스킴·로컬 파일 주소·로그인 정보가 포함된 URL은 받지 않는다.

### 갑옷

투구·흉갑·각반·부츠 북마크를 맞는 장비 칸에 놓거나 Shift+클릭하면 플레이어가 착용한다. 착용한 북마크는 원래 인벤토리 칸에서 장비 칸으로 이동하며 URL은 유지한다. 장비를 클릭하면 벗기·사이트 열기·편집 메뉴를 사용하고, 인벤토리로 끌어 벗을 수도 있다.

착용 모습에는 게임의 `humanoid` 및 `humanoid_leggings` 텍스처를 사용한다. 철·다이아몬드·금·사슬·네더라이트·구리·거북 계열 중 카탈로그에 포함된 장비를 지원한다. 틀린 부위나 일반 아이템을 장비 칸에 넣으면 거절한다. 벗을 빈칸이 없으면 현재 배치를 보존한다. 스킨 설정의 미리보기는 갑옷을 숨겨 스킨 자체를 확인할 수 있게 한다.

### 내 플레이어와 스킨

- 머리·몸·양팔·양다리에 스킨 좌표를 적용해 입체로 표시한다. 플레이어 드래그 또는 설정의 방향 슬라이더로 돌릴 수 있고, 인벤토리에서는 마우스 위치를 향해 머리와 몸이 함께 돌아간다.
- 마우스 목표는 각 플레이어의 실제 표시 크기와 눈 위치를 기준으로 계산한다. 머리는 더 크게·빠르게, 몸은 작은 각도로 조금 늦게 따라온다. 몸 추적은 ±0.16rad(약 ±9.2°), 머리와 몸을 합친 추적은 ±0.62rad 이내이며 이 숫자는 이 시안의 조정값이다. 실제 Minecraft 물리/애니메이션을 측정한 값으로 표현하지 않는다.
- 추적 회전은 수동 방향값에 별도로 더한다. 기본 스킨·겉옷·갑옷을 같은 몸 방향으로 그리며, 머리와 투구는 상대 고개 회전을 함께 사용한다. 화면 밖으로 마우스가 나가면 중립으로 돌아오고 보간이 끝나면 애니메이션 프레임을 멈춘다. 스킨 설정의 미리보기는 수동 방향 확인을 위해 추적 회전을 사용하지 않는다.
- 사이드바의 **설정 → 플레이어 스킨 변경**에서 PNG 파일을 적용한다. 인벤토리 안에는 스킨 변경 버튼을 두지 않는다.
- 지원 형식은 64×64 및 64×32 PNG. 클래식 4px 팔과 슬림 3px 팔은 사용자가 선택한다. 64×32는 클래식으로 표시하고 좌우 팔·다리를 대칭 처리한다. 고해상도 스킨과 망토는 이번 범위에 포함하지 않았다.
- 기본 스킨은 `ARU_Tris.png`다. 겉옷 레이어를 켜고 끌 수 있고 ARU_Tris로 복원할 수 있다. 기존 임시 생성 스킨은 제거했다.
- 스킨과 체형·겉옷 설정은 이 로컬 페이지의 브라우저 저장소에 보관한다. 새로고침 후 복원하며, 파일·폴더 경로나 Minecraft 계정은 요구하지 않는다. 사이트 데이터 삭제 시 스킨 설정도 지워진다.
- PNG 서명과 픽셀 크기를 확인하고 잘못된 파일은 기존 스킨을 보존한다. 로컬 저장이 불가능하면 저장 실패를 표시한다. 서버 업로드는 하지 않는다.

시안의 미리보기는 외부 라이브러리 설치 없이 Canvas에 큐브 면을 투영해 그린다. 스킨 맵의 면·몸체 위치는 공개된 [skinview3d 모델 정의](https://github.com/bs-community/skinview3d/blob/master/src/model.ts)와 대조했다. 본 프로젝트가 Minecraft 계정의 실제 게임 스킨을 변경하는 기능은 아니다.

## 광고 처리

기본 방향은 광고 요청 차단 + 화면의 광고 영역 정리. 두 처리를 결합해야 네트워크 요청과 남는 빈칸을 함께 다룰 수 있다. 광고 여부는 필터와 사이트별 규칙으로 판단한다. 모든 이미지를 광고로 취급해서 바꾸지 않는다.

| 모드 | 사용자에게 보이는 모습 | 설계 원칙 |
| --- | --- | --- |
| 광고 자리 접기 | 광고 상자와 여백을 접어 본문이 자연스럽게 이어짐 | 기본값 |
| 내 그림으로 바꾸기 | 탐지한 배너 자리에 등록한 이미지 표시 | 원래 광고 요청 차단은 유지. 광고 링크와 추적은 붙이지 않음 |
| 사이트별 예외 | 사용자가 허용한 사이트는 차단 해제 | 앱 구현 단계에 추가할 복구 수단 |

그림 대체는 배너처럼 안정된 크기의 광고 영역부터 적용한다. 모양이 불규칙한 피드 광고·전면 광고는 삭제를 우선하고, 사진을 억지로 덮지 않는다. 업로드한 사진은 크기에 맞춰 자르거나 여백을 두는 옵션을 검토한다. 웹사이트에 로컬 파일 경로·폴더 접근권한을 전달하지 않는다.

시안의 **원본과 비교**는 검토용으로 그린 가상 광고를 표시할 뿐, 광고 서버를 호출하거나 실제 차단을 해제하지 않는다. 선택한 파일도 메모리의 object URL로 표시하며 서버 업로드·영구 저장을 수행하지 않는다. 이 동작은 실제 사이트에서 대체가 성공했다는 증거가 아니다.

필터 오탐이나 레이아웃 깨짐이 생겼을 때 사이트별 복구가 가능해야 한다. 광고 숫자를 임의로 표시하거나 항상 완벽하게 차단된다고 표현하지 않는다.

### 유튜브

재생 전·중간 동영상 광고는 일반 배너 영역 대체와 다른 문제다. 유지되는 필터 엔진과 사이트 전용 대응이 필요하다. 유튜브의 변경이나 차단 감지에 따라 일시적으로 실패할 수 있으므로 **영구적·100% 차단을 보장하지 않는다**. 실제 구현 후 로그인 상태·계정·지역·여러 영상에서 재생과 광고 여부를 확인해야 한다.

영상 속에 제작자가 직접 삽입한 협찬 장면은 기본 광고 차단과 별도 범위다. 이번 구상에 자동 협찬 구간 건너뛰기는 넣지 않았다.

## 구현 후보 · 아직 확정하지 않은 사항

Windows 데스크톱의 UI 자유도와 개발 속도를 고려해 **Electron / Chromium을 1차 후보**로 제안한다. 웹사이트는 Electron의 `WebContentsView` 계열로 분리하고, 브라우저 UI와 외부 사이트의 권한을 나누는 방향이다. 공식 문서상 `BaseWindow`는 여러 웹뷰 조합을 지원하고, `BrowserView`는 폐기된 API이므로 신규 설계 기준으로 삼지 않는다. 프레임 없는 창은 별도 창 제어와 드래그 영역이 필요하다.

임의의 웹사이트를 일반 HTML `iframe`에 넣어 브라우저처럼 보이게 만드는 방식은 실제 브라우저 구현안으로 정하지 않는다. 이번 HTML은 외부 사이트를 불러오지 않는 디자인 자료다.

외부 콘텐츠에는 Node 통합을 허용하지 않고 격리·샌드박스를 사용한다. 광고 요청 처리에는 세션별 네트워크 필터링과 검증된 필터 엔진 연동을 검토한다. 배너 정리는 격리된 콘텐츠 처리 계층에서 수행한다. UI와 외부 웹뷰의 겹침·포커스·클립보드·IME 동작은 별도 기술 검증이 필요하다.

최신 Chromium이 있다는 이유만으로 Chrome의 모든 기능을 지원하는 것은 아니다. Google 로그인, DRM 영상, 비밀번호 저장·자동완성, 확장 프로그램, 인증서 오류 처리, 파일 다운로드, 권한 요청, 접근성은 실제 개발에서 별도로 확인한다. 이번 단계에서 지원 완료로 표시하지 않는다.

## 다음 구현 순서 제안

1. **지금:** 스타일·사이드바·광고 자리의 화면과 동작을 보고 방향 잡기.
2. **개발 모드의 실제 창:** 네이티브 창과 탭·주소·탐색, 사이드바 3개 상태. 패키징 없이 검증.
3. **기본 사용:** 즐겨찾기·다운로드·방문 기록·세션 복원·권한 요청. 개인 데이터 보존 확인.
4. **광고 처리:** 필터 자동 갱신, 배너 정리, 사이트별 복구, 로컬 그림 대체. 실제 사이트에서 검증.
5. **유튜브 등 특수 사이트:** 재생·로그인·광고 차단을 분리해서 확인. 실패 사례와 적용 범위 명시.
6. **최종:** 구현·개발 모드 검증을 마친 최종 배포 단계에서만 요청 범위에 맞게 EXE·포터블·설치 프로그램 제작.

이는 후속 구현 제안이며, 이번 요청에서 실제 앱 개발을 선행하지 않는다.

## 이번 시안의 검증 범위

시안에서 확인할 것: 폰트 로딩, 창 크기별 배치, 사이드바에 따른 콘텐츠 폭, 주소 입력창, 탭 조작, 두 재질, 가상 광고 접기·그림 대체와 로컬 이미지 선택. 2차 범위는 실제 포인터 드래그로 탭 배치, 공통 주소창의 포커스 전환, 탭별 독립 입력·이동 이력, 경계 비율 조절, 스킨 PNG 로딩·검사·저장·복원·체형·레이어·회전이다.

미구현/미검증: 외부 사이트 탐색, 실제 네트워크 광고 차단, 유튜브 광고 차단, 네이티브 창 제어, 브라우저 보안·DRM·로그인·확장 호환성, 장시간 사용감, 실제 모니터 크기의 가독성과 편안함.

원본 ZIP 해시와 현재 확인 결과는 `reference-manifest.json` 및 `design/evidence/verification.json`에 남긴다. 시안 확인 결과를 실제 브라우저의 통과 결과로 간주하지 않는다.

1·2차 확인 자료는 보존했다. 3차 화면·모델 테스트·실제 UI 조작 결과·원본 보존 기록은 `design/evidence/v3/`에 있다. 3차 진입점은 기존 `workspace.js`·`player.js`와 `inventory-model.js`·`bookmarks.js`·`resource-ui.css`이다. 실제 사이트를 탑재한 네이티브 브라우저, 광고 차단, 유튜브 재생의 작동 증거와 구분한다.

4차 자료는 `design/evidence/v4/`에 둔다. 모델 검사 27개는 지정 배치·정확한 URL·백업과 교체 실패·수동 아이콘 선택·재배치·장비와 아이콘 변경·저장 실패·다른 창의 선택 충돌을 확인한다. 실제 로컬 UI에서 아이콘 선택/편집/재배치/새로고침, 검색·분류·스크롤·취소, 갑옷 착용 후 아이콘 변경을 별도로 확인했다. 학교·메일 등 외부 사이트의 로그인이나 재생을 검증한 것은 아니다.

5차 자료는 `design/evidence/v5/`에 둔다. 언어·플레이어 모델 검사 20개와 기존 인벤토리 모델 검사 27개를 실행했다. 로컬 UI에서 영어 최초 화면, 한국어 즉시 변경과 재로딩 복원, 영어 복귀, 영어 아이콘 선택창/오류, 사용자 입력 보존과 예시 페이지를 확인했다. 좌우 마우스 입력 후 캔버스의 실제 렌더 회전과 캡처로 머리·몸의 같은 방향 추적을 확인한다. 외부 로그인이나 실제 브라우저 엔진 구현 완료의 증거와는 구분한다.
